# 🎙️ Локальний Голосовий Помічник (AI VTuber)

Проєкт локальної цифрової асистентки з інтелектуальною активацією на голос (**VAD**), розпізнаванням мовлення (**STT**), локальним штучним інтелектом (**LLM**) та реалістичним синтезом українського голосу (**TTS**). 

Головний цикл (`main.py`) — **послідовний**: записати → розпізнати → згенерувати відповідь → озвучити → дочекатись завершення → повторити. Це свідомий вибір під слабке залізо без GPU: просто, передбачувано, без гонок за ядра між STT/LLM/TTS. Паралелізм є лише всередині TTS-модуля (два допоміжні потоки на синтез і відтворення, детальніше нижче) — це не три незалежні наскрізні конвеєри, а одна точкова оптимізація, щоб перше речення озвучувалось, не чекаючи, доки синтезується весь монолог.

---

## 💻 Системні вимоги
* **Процесор (CPU):** Intel(R) Core(TM) i5-8265U @ 1.60GHz (4 ядра / 8 потоків).
  * Налаштовано динамічний розподіл потоків: **4 потоки** для важкого прорахунку промту (prefill), **1-2 потоки** для генерації токенів та **2-3 потоки** для рендеру звуку (PyTorch або ONNX Runtime — див. розділ TTS-рушії). Це запобігає перегріву, тротлінгу та помилкам типу `Access Violation (0xC0000005)`.
* **Оперативна пам'ять (RAM):** 12,0 ГБ (загальне споживання комплексу разом із моделями становить ~7-8 ГБ на PyTorch-рушії TTS, ~1 ГБ менше на ONNX-рушії — виміряно, див. нижче).
* **Відеокарта (GPU):** Інтегрована Intel UHD Graphics 620 (всі обчислення переведені на CPU).

## ⚙️ Налаштування та запуск

### 1. Створення віртуального оточення та встановлення залежностей

Проєкт розроблено та оптимізовано під **Python 3.11**. Відкрийте термінал у корені папки проєкту та виконайте:

```bash
# 1. Перевірте версію Python (має бути 3.11.x)
python --version

# 2. Створіть чисте віртуальне оточення .venv
python -m venv .venv

# 3. Активуйте створене віртуальне оточення
# Для PowerShell:
.\.venv\Scripts\Activate.ps1
# Для звичайного CMD:
.\.venv\Scripts\activate.bat

# 4. Оновіть pip
python -m pip install --upgrade pip

# 5. Встановіть бібліотеки
pip install -r requirements.txt

```

### 2. Завантаження ШІ-моделей

1. Покладіть файл моделі мислення `Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf` у папку `models/`.
2. Запустіть скрипт для автоматичного скачування ваг українського голосу StyleTTS2 та лінгвістичного вербалізатора чисел mBART:

```bash
python download_models.py

```

### 3. Налаштування FFmpeg

Переконайтеся, що у корені проєкту є папка `bin/`, де лежать `ffmpeg.exe` та `ffprobe.exe`. Модуль `tts_handler.py` автоматично додає їх до системного шляху (PATH) під час старту.

### 4. Запуск помічниці

```bash
python main.py

```

## 🛠️ Як це працює (послідовний цикл + точкова паралельність у TTS)

`main.py` — простий `while True`: кожен хід розмови виконується **по черзі**, а не як три постійно живі паралельні конвеєри:

```text
записати мікрофон → STT (Whisper) → LLM (Gemma, стрімом) → TTS (озвучити) → дочекатись кінця відтворення → повторити
```

Наступний запис мікрофона не почнеться, доки повністю не договорить попередня репліка (`tts_module.wait_until_done()` блокує цикл). Це навмисно просто — на 4-ядерному CPU без GPU постійні фонові STT/LLM/TTS-потоки, що борються за ядра одночасно з живим записом мікрофона, давали нестабільність і не окупались приростом швидкості.

1. **STT:** мікрофон пишеться через VAD (RMS-поріг), після `1.6` сек тиші зупиняється, і Whisper (`int8`) транскрайбить аудіо. `condition_on_previous_text=False` прибирає галюцинації на тиші.
2. **LLM:** отримує текст, генерує відповідь **стрімом**, ще під час генерації ріже готові речення й одразу передає їх у TTS (`tts_module.play_text_async(sentence)`) — не чекаючи, доки згенерується вся відповідь цілком.
3. **TTS:** `TTSHandler` тримає всередині себе **два допоміжні daemon-потоки** — `_text_processing_worker` (синтез, послідовно, шматок за шматком) і `_audio_playback_worker` (відтворення). Завдяки цьому, поки перший синтезований шматок вже грає у колонках, наступний вже може синтезуватись — і, оскільки ці потоки не блокують головний потік, синтез перших речень фактично встигає перекриватись у часі з тим, як LLM ще дописує решту відповіді. Це єдине справжнє розпаралелення в поточній архітектурі, і воно локальне до TTS-модуля, а не наскрізне на всю систему.

**Команди голосового переривання ("Стоп!") в поточній архітектурі немає** — вона існувала в попередній, черговій версії проєкту (три постійні потоки STT/LLM/TTS + `STOP_WORDS`), від якої свідомо відмовились через нестабільність на цьому залізі. Якщо бачиш згадки про це в старих гілках чи не до кінця злитих комітах — це залишок тієї архітектури, а не поточна поведінка.

`tts_handler.py` вміє синтезувати голос двома способами — через звичайний PyTorch-інференс `StyleTTS2` або через `onnxruntime`, якщо в `models/` лежить експортований `styletts2.onnx`. Перемикання — одним полем у `config.json`:

```json
"tts": {
  "engine": "onnx",
  "onnx_model_path": "models/styletts2.onnx"
}
```

**Виміряно на цьому залізі** (i5-8265U, `tts.n_threads=3`, той самий пресет, текстовий режим, ідентичні репліки):

| Метрика | `engine: pytorch` | `engine: onnx` | Різниця |
|---|---|---|---|
| Синтез шматка ~33 симв. | 3.98s | 3.02s | ~24% швидше |
| Синтез шматка ~68 симв. | 6.08s | 4.23s | ~30% швидше |
| RAM у стані спокою (`btop`, Mem) | 10.5G / 11.8G | 9.43G / 11.8G | ~1 ГБ менше |

Тобто ONNX виграє одразу за двома осями — і швидкістю, і пам'яттю — без відчутної різниці якості голосу.

**Обмеження ONNX-рушія:** експортований граф приймає лише готовий вектор стилю (`s_prev`) — у ньому немає voice-encoder'а. Тому **динамічне клонування голосу (`tts.mode=2`, `extract_voice_features` з `.wav`-референсу наживо) з `engine=onnx` не підтримується** — `TTSHandler` одразу кине зрозумілу помилку при старті, а не зламається посеред роботи. Для `mode=1` (готовий `.pt`-пресет) різниці між рушіями немає.

**Як отримати клонований голос і при цьому лишитись на швидкому ONNX:** клонування виносимо в окремий одноразовий офлайн-крок, а сам real-time пайплайн лишається на пресеті. Для цього — `extract_preset.py`:

```bash
python extract_preset.py
```

```bash
python extract_preset.py --audio sample.wav 

python extract_preset.py --audio references/sample.wav

python extract_preset.py --audio references/sample.wav --name "Мій голос"
```

Скрипт вантажить повну PyTorch-модель `StyleTTS2` лише один раз, викликає `model.extract_voice_features(audio_path)` для референс-аудіо з `references/` і зберігає результат як `<назва>.pt` у `voices/` (за замовчуванням — ім'я самого аудіофайлу; своє ім'я пресету можна задати через `--name`). Після цього просто вказуєш новий файл у `tts.preset_filename`, ставиш `tts.mode: "1"` і `tts.engine: "onnx"` — і отримуєш кастомний голос на швидкому рушії.

## 🎛️ Параметри конфігурації (`config.json`)

Анатомія оновленого файлу конфігурації для гнучкого налаштування балансу заліза:

```json
{
  "stt": {
    "model_size": "small",
    "device": "cpu",
    "compute_type": "int8"
  },
  "llm": {
    "model_path": "models/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf",
    "n_ctx": 512,
    "max_tokens": 200,
    "temperature": 0.7,
    "repeat_penalty": 1.18,
    "n_threads": 2,
    "n_threads_batch": 4,
    "n_batch": 256
  },
  "tts": {
    "engine": "onnx",
    "onnx_model_path": "models/styletts2.onnx",
    "mode": "1",
    "preset_filename": "Інна Гелевера.pt",
    "speed": 1.15,
    "noise_scale": 0.05,
    "n_threads": 2
  },
  "character": {
    "name": "Селті",
    "system_prompt": "Ти Селті, харизматична дівчина-стрімер. Твій стиль розмови: живий, впевнений, з легким сарказмом та піддражнюванням. Говори як реальна людина на трансляції, будуй звичайні повні речення. КРИТИЧНЕ ПРАВИЛО: Використовуй тільки чисті літературні та розмовні слова, які легко вимовити. Жодних текстових звуків, зітхань чи вигуків."
  },
  "text_mode": false
}

```

### Ключові параметри оптимізації потоків:

* `llm.n_threads_batch`: Виставляється на рівні `4` (максимум фізичних ядер). Прискорює обробку вхідного запиту користувача.
* `llm.n_threads`: Виставляється на рівні `2` або `1`. Кількість ядер під час покрокового виведення слів.
* `tts.n_threads`: Виставляється на рівні `2` або `3`. Потужність, що виділяється TTS-рушію для генерації хвиль (діє однаково і на PyTorch, і на ONNX — для ONNX мапиться в `intra_op_num_threads`).
* **Правило балансу:** Сума `llm.n_threads` + `tts.n_threads` не повинна суттєво перевищувати кількість твоїх фізичних ядер (`4`), щоб уникнути взаємного блокування та тротлінгу процесора під час одночасної роботи (генерація + озвучка).

### Перемикач TTS-рушія:

* `tts.engine`: `"pytorch"` (дефолт, підтримує клонування голосу `mode=2`) або `"onnx"` (швидше й економніше по RAM, лише готові `.pt`-пресети, `mode=1`). Деталі й виміри — у розділі "⚡ TTS-рушії" вище.
* `tts.onnx_model_path`: шлях до `.onnx`-файлу (відносний — від кореня проєкту, або абсолютний). Використовується лише коли `tts.engine="onnx"`.

## 🔗 Використані ШІ-технології та Джерела

* **[Faster-Whisper](https://github.com/SYSTRAN/faster-whisper)** — оптимізований двигун `CTranslate2` для Whisper.
* **[Llama.cpp Python](https://github.com/abetlen/llama-cpp-python)** — інференс GGUF моделей на CPU.
* **[Gemma-4-E4B-Uncensored-HauhauCS-Aggressive](https://huggingface.co/HauhauCS/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive)** — емоційна модель на базі архітектури Gemma.
* **[StyleTTS2 Inference UA](https://github.com/patriotyk/styletts2-inference)** — адаптований синтез мовлення під українську мову (by `@patriotyk`).
* **[ONNX Runtime](https://onnxruntime.ai/)** — опційний прискорений рушій інференсу для `styletts2.onnx` (~25-30% швидше, ~1 ГБ менше RAM за виміром на CPU без клонування голосу).
* **[Ukrainian Word Stress](https://www.google.com/search?q=https://github.com/patriotyk/ukrainian-word-stress)** — алгоритм автоматичної розстановки наголосів.
* **[IPA UK](https://www.google.com/search?q=https://github.com/patriotyk/ipa-uk)** — фонетичний конвертер тексту в IPA.
* **[SoundDevice](https://python-sounddevice.readthedocs.io/)** — низькорівнева робота з аудіопотоками Windows.
