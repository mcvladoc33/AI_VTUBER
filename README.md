# 🎙️ Локальна Голосова Помічніка (AI VTuber Core)

Проєкт локальної цифрової асистентки з інтелектуальною активацією на голос (**VAD**), розпізнаванням мовлення (**STT**), локальним штучним інтелектом (**LLM**) та реалістичним синтезом українського голосу (**TTS**). 

Система повністю переведена на **асинхронну архітектуру паралельних конвеєрів (черг)**. Вона оптимізована для максимальної чуйності та швидкого старту мовлення на CPU без використання відеокарти, запобігаючи фризам звуку та крашам Windows.

---

## 💻 Системні вимоги
* **Процесор (CPU):** Intel(R) Core(TM) i5-8265U @ 1.60GHz (4 ядра / 8 потоків).
  * Налаштовано динамічний розподіл потоків: **4 потоки** для важкого прорахунку промту (prefill), **1-2 потоки** для генерації токенів та **2-3 потоки** для рендеру звуку в PyTorch. Це запобігає перегріву, тротлінгу та помилкам типу `Access Violation (0xC0000005)`.
* **Оперативна пам'ять (RAM):** 12,0 ГБ (загальне споживання комплексу разом із моделями становить ~7-8 ГБ).
* **Відеокарта (GPU):** Інтегрована Intel UHD Graphics 620 (всі обчислення переведені на CPU).

## ⚙️ Налаштування та запуск

### 1. Створення віртуального оточення та встановлення залежностей

Проєкт розроблено та оптимізовано під **Python 3.11**. Відкрийте термінал у корені папки проєкту та виконайте:

```bash
# 1. Перевірте версію Python (має бути 3.11.x)
python --version

# 2. Створіть чисте віртуальне оточення .venv
python -m venv .venv

# 3. Активуйте створене віртуальне оточення
# Для PowerShell:
.\.venv\Scripts\Activate.ps1
# Для звичайного CMD:
.\.venv\Scripts\activate.bat

# 4. Оновіть pip
python -m pip install --upgrade pip

# 5. Встановіть бібліотеки
pip install -r requirements.txt

```

### 2. Завантаження ШІ-моделей

1. Покладіть файл моделі мислення `Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf` у папку `models/`.
2. Запустіть скрипт для автоматичного скачування ваг українського голосу StyleTTS2 та лінгвістичного вербалізатора чисел mBART:

```bash
python download_models.py

```

### 3. Налаштування FFmpeg

Переконайтеся, що у корені проєкту є папка `bin/`, де лежать `ffmpeg.exe` та `ffprobe.exe`. Модуль `tts_handler.py` автоматично додає їх до системного шляху (PATH) під час старту.

### 4. Запуск помічниці

```bash
python main.py

```

## 🛠️ Як це працює (Асинхронна архітектура)

Проєкт використовує концепцію **трьох незалежних асинхронних конвеєрів**, які працюють паралельно і спілкуються через безпечні системні черги (`Queue`):

```text
[Поток 1: STT] ──(Текст запису)──> [Поток 2: LLM] ──(Шматки тексту)──> [Поток 3: TTS] ──> Спікер

```

1. **Потік 1: Введення/STT (Вхідний конвеєр):**
* Моніторить мікрофон за допомогою VAD (Voice Activity Detection). Запис активується, коли RMS гучність перевищує `threshold`.
* Після `1.2` сек тиші запис зупиняється і Whisper (квантування `int8`) миттєво транскрайбить аудіо в текст. Прапорець `condition_on_previous_text=False` повністю ліквідує галюцинації у тиші.


2. **Потік 2: Обробка/LLM (Конвеєр мислення):**
* Отримує текст користувача. Для первинного прорахунку контексту (prefill) задіює параметр `"n_threads_batch": 4`, щоб максимально швидко "розворушити" модель.
* Під час генерації токенів перемикається на `"n_threads": 2` (або `1`), звільняючи ядра для паралельного рендеру звуку.
* Одразу ріже вихідний емоційний текст на речення (ігноруючи розділові знаки всередині лапок `«»` або `""`) і миттєво перекидає перші готові шматки в чергу звуку, не чекаючи завершення всієї думки.


3. **Потік 3: Озвучка/TTS (Вихідний конвеєр):**
* Працює на базі `StyleTTS2 Inference UA` з апаратним обмеженням кроків дифузії (зменшено до 3 ступенів), що прискорює генерацію вдвічі.
* Потоком `PyTorch` керує інструкція `torch.set_num_interop_threads(1)` для ліквідації оверхеду на CPU.
* Щойно перший шматочок аудіо згенеровано, він миттєво відправляється у динаміки, поки наступні речення паралельно прораховуються у фоні.



### 🛑 Функція екстреного переривання (Команда СТОП)

У систему інтегровано механізм миттєвого очищення конвеєра. Якщо користувач під час мовлення помічниці каже команду переривання (наприклад, *"Стоп!"*), черги LLM та TTS миттєво скидаються, аудіо-плеєр примусово зупиняє відтворення, а система миттєво переходить у режим очікування нової репліки, не чекаючи доки модель "договорить".

## 🎛️ Параметри конфігурації (`config.json`)

Анатомія оновленого файлу конфігурації для гнучкого налаштування балансу заліза:

```json
{
  "stt": {
    "model_size": "small",
    "device": "cpu",
    "compute_type": "int8"
  },
  "llm": {
    "model_path": "models/Gemma-4-E4B-Uncensored-HauhauCS-Aggressive-Q4_K_M.gguf",
    "n_ctx": 512,
    "max_tokens": 200,
    "temperature": 0.7,
    "repeat_penalty": 1.18,
    "n_threads": 2,
    "n_threads_batch": 4,
    "n_batch": 256
  },
  "tts": {
    "mode": "1",
    "preset_filename": "Інна Гелевера.pt",
    "speed": 1.15,
    "noise_scale": 0.05,
    "n_threads": 2
  },
  "character": {
    "name": "Селті",
    "system_prompt": "Ти Селті, харизматична дівчина-стрімер. Твій стиль розмови: живий, впевнений, з легким сарказмом та піддражнюванням. Говори як реальна людина на трансляції, будуй звичайні повні речення. КРИТИЧНЕ ПРАВИЛО: Використовуй тільки чисті літературні та розмовні слова, які легко вимовити. Жодних текстових звуків, зітхань чи вигуків."
  },
  "text_mode": false
}

```

### Ключові параметри оптимізації потоків:

* `llm.n_threads_batch`: Виставляється на рівні `4` (максимум фізичних ядер). Прискорює обробку вхідного запиту користувача.
* `llm.n_threads`: Виставляється на рівні `2` або `1`. Кількість ядер під час покрокового виведення слів.
* `tts.n_threads`: Виставляється на рівні `2` або `3`. Потужність, що виділяється моделі StyleTTS2 для генерації хвиль.
* **Правило балансу:** Сума `llm.n_threads` + `tts.n_threads` не повинна суттєво перевищувати кількість твоїх фізичних ядер (`4`), щоб уникнути взаємного блокування та тротлінгу процесора під час одночасної роботи (генерація + озвучка).
